# COLOR WORLD — مشروع المصدر

**الحالة: مشروع تنفيذ غير متحقق بالبناء الأصلي. ليس APK جاهزًا، ولم يستوفِ تعريف اللعبة النهائية في وثيقة الطلب.**

أُنشئ مشروع Godot 4.4.1 يستهدف Android وiOS باستخدام الرسم الأصلي للمحرك، دون HTML أو WebView. الملفات تشمل الأنظمة ومحتوى جميع المناطق، وليس أول 15 مستوى فقط.

## محتويات التسليم

- 100 تعريف منطقة متصلة في شبكة واحدة، لكل منها معلم مسمى ووصف هندسي.
- 1500 مستوى، و1500 مجموعة طلاء فعلية في البيانات، بإجمالي 10646 جزءًا هندسيًا.
- 200 وصف نوعي للمجسمات، مركبة من خمس بدائيات هندسية؛ هذه أصول إجرائية وليست نماذج فنية يدوية لكل منطقة.
- مزج RGB بوحدات 0.1% مع مجموع 100%، وعرض فوري للون، وتقييم OKLab عند المطابقة فقط.
- النجوم والعملات وفروق مكافأة التحسين والمتجر والمساعدات الثلاث.
- الحفظ المحلي مع ملف مؤقت وبصمة SHA-256 ونسخة سابقة، وإعادة بدء بضغطة مطولة.
- كاميرا العالم، تحميل المناطق القريبة، كشف الطلاء وإعادة الطلاء، ومؤثرات الحركة.
- 49 ملف WAV أصليًا: مؤثرات وموسيقى بطبقات وأجواء بيئية مولدة صوتيًا.
- واجهات عربية وإنجليزية، خط عربي مضمّن، وإعدادات الصوت والاهتزاز والجودة.
- اختبارات Godot لمنطق اللعبة والحفظ ومسار 1–1500؛ موجودة **ولم تُشغّل** هنا.
- مولدات محتوى وصوت، ومدقق بيانات، وأداة بناء، وتعريف بناء آلي لـGitHub Actions.

## التحقق الذي تم فعليًا

راجع `docs/content_validation_report.json`: فحص البيانات والحسابات المستقل نجح دون أخطاء. يراجع وجود الربط الهندسي والكاميرات والمكافآت، وعدد المناطق والمستويات، وإمكانية بلوغ كل Target حسابيًا، واللغات والصوت ومراجع الملفات.

هذا الفحص **ليس تنفيذًا لمحرك Godot**. الفحص البنيوي للنص البرمجي ليس بديلًا عن compiler. مسار التقدم المحسوب لا يثبت أن الواجهات تعمل على هاتف.

جرت محاولة البناء باستخدام `tools/build.py`، وتوقفت لأن Godot غير مثبت. تنزيل المحرك لم يكتمل في بيئة التنفيذ المقيدة بالشبكة. لا يوجد APK أو IPA أو فيديو تشغيل فعلي ضمن التسليم.

## التشغيل على جهازك

1. ثبّت **Godot 4.4.1 Standard**.
2. فك ضغط المجلد كاملًا.
3. في نسخة GitHub، نفّذ `python tools/prepare_assets.py` لتجهيز البيانات والصوت والخط، ثم افتح `project.godot` من Godot واترك استيراد الخط والصوت يكتمل.
4. اضغط F6/F5 لتشغيل المشهد/المشروع. التشغيل الأول يحتاج مراجعة أخطاء الاستيراد أو البرمجة إن ظهرت؛ لم يُتحقق هنا من خلوها.

للاختبارات داخل مجلد المشروع، بعد إتاحة `godot` في PATH:

```text
godot --headless --editor --import --quit
godot --headless --script tests/test_game.gd
godot --headless --script tests/smoke_scene.gd
python tools/validate_content.py
```

اختبار `test_game.gd` يستخدم ملفات باسم `qa_color_world` بعيدًا عن حفظ اللاعب. اختبار المشهد يستخدم المشروع الحقيقي، فيُفضّل تشغيله بملف مستخدم تجريبي.

## تصدير Android

ثبّت قوالب تصدير Godot المطابقة وOpenJDK 17 وAndroid SDK، ثم اضبط مساري Java SDK وAndroid SDK في إعدادات محرر Godot. اختر إعداد التصدير Android، أو نفّذ:

```text
python tools/build.py --platform android
```

الأداة تستورد المشروع، وتشغّل اختبارات Godot، ثم تحاول إنشاء `build/COLOR_WORLD.apk`. تتوقف عند فشل أي خطوة ولا تعتبر وجود المصدر نجاحًا للبناء. البناء الافتراضي Debug للتجربة، ولم يُنتَج هنا.

المتطلبات موثقة في [دليل تصدير Android الرسمي](https://docs.godotengine.org/en/4.4/tutorials/export/exporting_for_android.html).

## تصدير iOS

التصدير يتطلب macOS وXcode، وقوالب التصدير، وتعيين Apple Team ID الخاص بصاحب التطبيق في إعداد iOS. لم تُضف هوية توقيع مفترضة. راجع [دليل iOS الرسمي](https://docs.godotengine.org/en/4.4/tutorials/export/exporting_for_ios.html).

## ما لم يُعتمد بعد

- نجاح compilation واستيراد المشروع وتشغيل المشاهد الأصلية.
- APK مُثبت على Android، أو مشروع Xcode مبني على iOS.
- اختبارات لعب حقيقية للحفظ والمتجر والإعادة ونهاية العالم.
- فحص بصري للواجهات وRTL وSafe Area على أحجام ونسب شاشات مختلفة.
- قياسات 60 FPS والذاكرة والحرارة واستهلاك البطارية.
- معايرة التقييم إدراكيًا مع لاعبين؛ معامل OKLab الحالي إعداد أولي صريح.
- مستوى الفن المطلوب في الوثيقة: تنوع الأسماء والوصفات لا يساوي اعتماد 100 منطقة بجودة فنية نهائية. بعض الأنواع تشترك في بنية إجرائية، وتحتاج مراجعة وتصميمًا أدق.
- جودة الأجواء الموسيقية والمؤثرات على الهاتف، والاهتزاز على iOS.

هذه نقاط تمنع وصف المشروع بأنه **FULL GAME مكتملة ومختبرة**. التفاصيل موجودة في `docs/IMPLEMENTATION_STATUS.md`.

## إعادة توليد المحتوى

```text
python tools/generate_content.py
python tools/generate_audio.py
python tools/validate_content.py
```

يحتاج مولد الصوت NumPy. تشغيل اللعبة لا يحتاج Python أو اتصالًا بالإنترنت؛ Python مخصص لأدوات الإنتاج والتحقق. في نسخة GitHub، يتم توليد البيانات والصوت قبل الاستيراد؛ نسخة ZIP السابقة تحتوي الناتج جاهزًا.
